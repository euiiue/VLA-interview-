# 第一部分：深度学习与 Transformer

## Q1. 马尔可夫性质是什么？在机器人控制中什么时候不成立？

如果状态 sₜ 已包含预测未来所需的信息，则 P(sₜ₊₁|s₀:ₜ,a₀:ₜ)=P(sₜ₊₁|sₜ,aₜ)，称为马尔可夫性质。它针对的是完整状态，不要求单帧图像本身具有马尔可夫性。

机器人实际看到的是观测 oₜ：遮挡物体、不可见接触力、未观测速度、相机延迟会使相同图像对应不同真实状态，因此仅用 oₜ 决策通常是部分可观测问题。可引入多帧历史、关节速度、力觉、动作历史和时间戳，或用记忆网络/状态估计形成 belief state。要同时测量延迟并进行对齐，否则加历史也可能引入错配。

## Q2. Transformer 的 Q、K、V 和形状

对输入 X∈R^(B×L×D)，分别线性投影 Q=XWQ、K=XWK、V=XWV。若头数 H，D=H·dₕ，拆分后 Q/K/V 通常是 B×H×L×dₕ。注意力为 softmax(QKᵀ/√dₕ + mask)V，得 B×H×L×dₕ；合并头后是 B×L×D，再做输出投影。交叉注意力的查询长度 Lq 与键值长度 Lk 可以不同。

除以 √dₕ 是为了控制点积的量级，避免维度增大导致 softmax 过度饱和、梯度变小。mask 应在 softmax 前屏蔽不可访问的位置。

## Q3. 单头与多头注意力

单头用一组投影在一个表示子空间计算注意力；多头用不同的 Q/K/V 投影并行计算，每个头可学习不同关系，再拼接并投影。多头**有能力**关注不同信息，但不能保证每个头一定有明确、互不重叠的语义。固定总维度 D 时，每头维度通常为 D/H，多头不是简单地把模型参数乘 H；具体参数量取决于投影实现。

## Q4. Transformer 完整 Forward

输入 token 经过 embedding，结合绝对/相对位置信息；每个 block 依次进行注意力、残差与归一化、逐位置 FFN、残差与归一化。实际顺序依实现而异：Pre-LN 先归一化再进子层，Post-LN 则在残差之后。FFN 提供非线性变换；残差便于梯度传播，LayerNorm 稳定激活。

Encoder 通常双向看可见输入；自回归 Decoder 用因果 mask 禁止读取未来 token；标准 Encoder-Decoder 的 decoder 还通过 cross-attention 读取 encoder 输出。多模态机器人模型的 attention mask 可按图像、语言、状态、动作块专门设计，不必机械套用标准结构。

## Q5. 连续轨迹的位置编码

绝对位置编码表示 token 所处索引；相对位置编码建模 token 间距离；RoPE 通过对 Q/K 做位置相关旋转，使相对位置信息体现在点积中。序号不能自动表达真实物理时间：不均匀采样时应提供实际时间戳或 Δt，必要时对真实时间做连续编码。

机器人位姿还要明确坐标系、单位及旋转表示；姿态宜用四元数或 6D 表示并处理约束。动作 chunk 同时需要标记动作在预测时刻之后的时间偏移，训练、部署的采样周期必须一致或显式重采样。

## Q6. KV Cache

自回归生成中，历史 token 的各层 K/V 不变时可缓存，只为新 token 计算 Q/K/V 并读取历史缓存，避免每步重算整个前缀。每层常见缓存形状为 B×Hkv×Lcache×dₕ；GQA/MQA 的 KV 头数可小于 query 头数。缓存减少重复计算但增加显存与访存。

缓存只能在模型权重、输入、位置编码、mask 和上下文前缀完全一致时复用。新 episode、指令改变、图像或状态改变、动作历史回滚，相关缓存应失效；不能把旧图像的缓存当成新观测。连续动作的迭代去噪中，可复用不变的视觉语言前缀，但变化的噪声动作和时间条件通常须重新计算，详见 Q59。

## Q7. 交叉熵

logits z 经过 softmax 得到 pᵢ=e^zᵢ/Σⱼe^zⱼ，单标签交叉熵 L=−log pᵧ；它等价于最小化真实类别的负对数似然。实现时使用 log-softmax 或 log-sum-exp，并先减去最大 logit 以避免溢出；框架的 cross_entropy 接收 logits，通常不应提前再做一次 softmax。

离散动作 token、类别标签可用交叉熵；连续位置、姿态、速度更常用回归或分布生成目标。对多模态动作，单一 MSE 可能平均不同可行动作，得到无效的中间结果。

# 第二部分：VLA 架构与模型

## Q8. RT-2、OpenVLA、π₀、π₀.₅ 的区别

RT-2 将动作编码成文本 token，使用视觉语言模型的自回归生成，借助网络视觉语言知识；OpenVLA 是开源 VLA 路线，也以离散动作 token 为核心，便于基于已有 VLM 训练和社区适配。两者的具体视觉主干、训练数据、token 化方式不同。

π₀ 使用视觉语言主干和动作专家，通过 Flow Matching 生成连续动作 chunk；π₀.₅ 在此基础上强调异构数据协同训练、开放世界泛化及分层语义能力。离散自回归适合统一语言训练但会有量化和逐 token 延迟；连续 chunk 对精细连续控制友好，但采样步数、执行衔接和部署一致性同样重要。性能取决于数据、控制接口和评测，不可单按模型名排序。

## Q9. π₀ 与 π₀.₅ 的核心区别

两者都可由 VLM 提取视觉语言条件，通过 action expert 对连续动作序列学习速度场。π₀.₅ 更强调不同来源机器人数据、网络视觉语言/语义数据及高低层任务信息的协同，让任务泛化更强；这不等于所有新场景零样本成功。

以官方 OpenPI 的默认配置为例，π₀ 把连续机器人 state 投影为 action expert 的 suffix token；π₀.₅ 默认将 state 离散化后与语言提示共同送入 VLM 前缀，动作专家以 AdaRMSNorm 注入时间条件。**实现可有配置覆盖**，须核对实际 checkpoint、tokenizer 和代码，不要把默认值说成所有实现的硬约束。[OpenPI 配置](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0_config.py)、[模型代码](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0.py)。

## Q10. π₀.₅ 的 Gemma/VLM 和动作专家

视觉编码器把多相机图像转成视觉 token，语言指令以及经处理的状态进入 VLM 前缀，形成面向任务的语义与视觉条件；基于 Gemma 的动作专家处理噪声动作 token 和流时间条件，并通过受控 attention 读取前缀信息，预测每个动作维度的速度场。随后从噪声迭代积分生成连续动作 chunk。动作专家不是简单地把文字翻译为固定动作，也不是独立于视觉语义工作的控制器。缓存前缀只适用于条件在一次采样中保持不变。

## Q11. π₀.₅ 预训练与多模态对齐

机器人数据提供图像、语言、状态、动作的时序对应；其他视觉语言数据提供语义、识别或高层任务监督。不同机器人需要明确各自动作空间、mask、本体标识及归一化，不能假设所有维度物理意义相同。配对训练让语义条件与可执行动作建立联系，但并非每条样本都必须同时具备所有模态。

预训练主要提供视觉语义和跨任务先验；下游微调适配实际相机、硬件、动作接口及任务分布。具体训练混合比例、冻结策略和数据范围要以论文/训练配置为准，不应凭借项目部署经历声称自己完成了基础模型预训练。

## Q12. FAST

FAST 是动作序列 token 化方法：对动作 chunk 沿时间维做离散余弦变换 DCT，将频域系数量化，再利用 BPE 等方式压缩为 token，降低序列长度，可用于自回归动作预测或相关预训练。压缩后的 token 需要解码还原为连续动作。

它与连续 Flow Matching 的区别是训练目标和生成路径：FAST 常用离散 token 的交叉熵、自回归解码；Flow Matching 学速度场并积分生成连续 chunk。压缩率与量化误差依动作频谱和配置变化，不能保证对所有高频精细动作无损。[FAST 论文](https://arxiv.org/abs/2501.09747)。

## Q13. LAPA 潜在动作预训练

LAPA 利用无机器人动作标签的视频，先学习由相邻或间隔帧变化得到的离散潜在动作，再训练模型根据观测和任务预测这些潜在动作，最后用少量带机器人动作标签的数据微调到实际动作空间。它扩大可利用的视频数据范围，但潜在动作不天然等于电机指令，视觉变化还可能来自相机运动或遮挡，因此仍需动作落地、时序与本体对齐。[LAPA 论文](https://arxiv.org/abs/2410.11758)。

## Q14. 离散动作与连续动作

离散 token 可直接复用语言模型和交叉熵，表达多峰分布方便，但量化可能损失精度，自回归序列过长带来延迟。连续生成避免固定分桶的量化误差，更适合连续高维动作，但仍受模型表达、采样步数及训练数据限制；动作连续也不自动保证轨迹平滑或安全。需共同比较任务成功率、毫米级误差、控制频率、推理尾延迟和部署成本。

## Q15. 厂商 VLA 与 RT-2/OpenVLA

不能在缺少具体公开论文或版本时推断智元内部架构。可按公开资料逐项比较：视觉语言骨干与动作头、动作表示和频率、多本体数据、推理硬件、控制接口与评测任务。工业系统还要关注限位、急停、异常恢复、重复定位与长时稳定性。面试中可说：“我会先确认其具体模型版本和公开材料，再比较端到端指标；不会从品牌名推断技术细节。”

## Q16. 如何设计 VLA 系统

先定义任务精度、物体/环境变化、硬件自由度、可用数据和最大端到端延迟。单任务、数据少、算力有限可先做 ACT/轻量 BC；要求语言语义泛化时选 VLM 加动作专家；精细连续动作可比较 Flow Matching，离散自回归则便于统一预训练。以相同数据量和控制周期比较成功率、耗时、P95 延迟、干预率和碰撞。

单臂重点在定位、接触和安全；双臂额外要同步、互避和共享物体约束；人形还需平衡、全身控制与更复杂的动作接口。策略输出必须经过控制层约束，不能只看模型离线 loss。

## Q17. VLA 与世界模型

VLA 主要学习从观测和指令到动作的策略；世界模型主要预测动作条件下的未来观测、潜在状态或奖励。前者可直接执行但可能缺乏长视野预测，后者可用于候选动作评估、规划、异常检测和生成训练数据，但长期预测误差与仿真偏差会累积。结合时可用世界模型筛选 VLA 的候选 chunk，再按真机反馈重规划；必须测模型误差对最终控制的影响，不能以视频看起来真实就断言控制有效。

## Q18. 为什么选 π₀.₅ 作 Baseline

参考表述：“在我的项目中，π₀.₅ 具有预训练视觉语言能力，并支持连续动作 chunk，适合研究工业操作中的感知与精细动作衔接；我也完成了数据和机械臂接口适配。但它不是天然最优，我会在同数据、同硬件和评估协议下与 ACT、Diffusion Policy 以及合适的 OpenVLA 版本比较成功率、泛化、延迟和资源。”

ACT 往往适合作为轻量任务基线，Diffusion Policy 是连续动作生成的重要对照，OpenVLA 代表离散动作路线。实际谁更优须看微调配置与实测，不能虚构比较成绩。

## Q19. VLA 的改进与瓶颈

关键问题包括长时任务状态记忆、误差积累与恢复，接触不可见、多本体动作不统一，数据成本与场景偏差，以及时延/安全约束。结合简历，我会优先研究“动作块执行期间的时延、丢帧与前缀不一致如何影响鲁棒性”，对应 ExecShift 的研究方向，但不擅自补充论文结果。

可先固定模型与数据，分级注入延迟和抖动，测成功率、偏差、jerk、干预率；再比较异步执行、RTC 和更强观测条件，分离系统与模型收益。创新应有可复现协议及负结果，而不只靠单场景演示。

# 第三部分：Flow Matching 与动作生成

## Q20. Flow Matching 原理

设真实动作块 x₁∼p_data，噪声 x₀∼N(0,I)，t∼U(0,1)，采用直线路径 xₜ=(1−t)x₀+tx₁，则条件目标速度 uₜ=x₁−x₀。网络在观测条件 c 下拟合 vθ(xₜ,t,c)，目标 L=E‖vθ(xₜ,t,c)−(x₁−x₀)‖²；这是条件流匹配的一个常见构造。最优预测对应给定 xₜ 和条件下目标速度的条件期望。不同实现可反向定义时间，符号随之反转。

推理时解 ODE dx/dt=vθ，从噪声积分到数据。扩散方法通常通过噪声预测/score 和随机或确定性采样构建生成过程；两者有联系但训练目标及路径设计不完全相同。连续生成有利于表示高维、多模态动作块，实际精度取决于模型、数据与采样。

## Q21. 训练和采样流程

训练：取配对的图像、指令、状态和真实动作块；采样噪声 x₀ 与时间 t，构造 xₜ 和目标速度；预测速度并对有效动作维度计算 MSE，反向更新参数。推理：获取观测条件，采样初始噪声，按时间步多次预测速度，用 Euler 等积分得到动作，反归一化后执行。训练常一次随机时间监督，推理则多次模型调用；评估时须同时记录随机种子、采样步数、动作转换与整体延迟。

## Q22. 推理步数是否越多越好

更多步数通常减小数值离散误差，但模型误差、训练路径误差和实时性损失不会因此消失，甚至因为新观测到达更晚使真机表现下降。固定其他设置比较例如 2、4、8、16 步，报告任务成功率、轨迹误差、P50/P95 端到端延迟、动作边界变化以及每秒控制预算；重复多个场景和随机种子。最优步数是控制质量与延迟共同决定的。

## Q23. 为什么预测多个动作只执行一部分

一次预测 H 步能建模动作间时序并摊薄推理成本；只执行 h≤H 步后重新观测，可纠正模型误差和环境变化。假设 30 Hz 下 H=50，覆盖约 1.67 秒；若执行 h=10，约 0.33 秒后重规划，但这只是算例，h 要由推理耗时、任务动态及缓冲余量决定。

h 太大易开环漂移，太小可能推理跟不上或频繁切换。重叠动作可做 temporal ensembling 或平滑；窗口太大会迟滞、磨掉抓取接触动作。应检查成功率、动作延迟、边界跳变与 jerk，而不是规定“50 步必须执行某个固定值”。

## Q24. ACT 与 RTC

ACT 使用动作块预测，常对多个时刻预测的重叠动作做时间集成以改善平滑，实际执行方式由实现决定；它本身不保证处理异步推理延迟。RTC 则在旧 chunk 继续执行的同时预测新 chunk，并对已承诺的动作前缀做条件约束，使新旧动作衔接。推理期 RTC 用类似 inpainting 的引导；训练期 RTC 通过训练学会前缀条件。

Temporal ensembling 是重叠预测加权平均；一般 smoothing 是对轨迹滤波；RTC 关注延迟期间已承诺动作与未来生成的一致性。它们可组合但不能互相等同。[RTC 论文](https://arxiv.org/abs/2506.07339)。

# 第四部分：数据采集与处理

## Q25. 如何设计数据采集

从任务接触速度、目标精度和控制接口倒推采样频率；系统由遥操作设备、机器人与末端、相机、状态/动作采集、统一时钟、录制与数据校验组成。给图像、状态和命令分别打时间戳，测量固定延迟和抖动，按规则匹配或插值，保留原始时间戳与对齐误差。

先采集小规模试点验证成功率和失败模式，再增加物体、位置、光照、操作者及恢复状态的覆盖，按 episode/场景划分训练和测试，避免相邻帧泄漏。条数没有通用答案；不同人采集可增加多样性，也可能带来动作风格冲突，需要一致的标定与质量标准。结合简历可介绍你搭建的 GELLO + LeRobot 流程，但数量和频率须【待核实】。

## Q26. 关节角还是末端位姿

关节动作易直接控制并保留冗余关节信息，但依赖具体本体和关节顺序；末端位姿便于表达空间任务及跨机械臂迁移，却需要可靠的 IK、坐标系和末端工具标定。绝对动作便于明确目标，但受标定和坐标漂移影响；相对动作通常方便迁移，却可能因积分和时间步错误累积误差。

RPY 直观但有奇异及角度跳变；旋转向量紧凑但在某些边界不连续；四元数需归一化并处理 q 与 −q 等价；6D 表示连续性较好但需正交化。跨本体至少统一坐标系、单位、TCP、动作语义、频率、夹爪方向，并针对不同工作空间处理 IK 和限位。

## Q27. 相机标定

内参包含焦距、主点和畸变系数，可用棋盘格/标定板多角度采集求解；外参描述相机与机器人基座或末端的刚体变换。Eye-in-hand 相机固定于末端，需手眼标定求工具到相机变换；eye-to-hand 相机固定在外部，求基座与相机关系。多相机统一到基座系时应统一变换方向，并验证矩阵链。

用未参与标定的点测重投影误差和真实空间误差；在工作空间多位置、多深度验证，最终用抓取/插装误差检验。重投影小不代表手眼外参和 TCP 必然准确，还要核对机械臂位姿、时间同步和标定板移动方式。

## Q28. 深度图点云与 VR 尺度

对像素 (u,v) 和以相机光轴为深度的 Z，针孔模型 X=(u−cₓ)Z/fₓ，Y=(v−cᵧ)Z/fᵧ；先处理深度单位和畸变，再通过 p_base=T_base_camera·p_camera 得到基座坐标。若设备给的是射线距离而非 Z，必须先按设备定义转换；还需处理无效深度和时间同步。

VR 遥操作可在启用时记录手柄和末端相对零点，增量映射 Δp_robot=sRΔp_VR，并根据姿态定义组合旋转；比例 s 可按工作空间和精度确定。配合平滑、速度/位置限幅、工作区约束、失联停止；不要将 VR 坐标直接当机器人坐标。你的简历明确提到相对零点、低通和限幅，具体比例与姿态公式【待核实】。

## Q29. LeRobot 转换及 v3/v2.1

先定义机器人 state、action 的维度、单位、坐标系、关节顺序、采样频率和图像键；将原始时间序列按 episode 对齐，保存帧、相机视频、任务文本及元数据，再计算仅来自训练集的归一化统计。转换完成后抽样回放，检查起止帧、时间戳单调性、丢帧、动作和观测相位、维度、视频与 parquet 帧数和异常值。

v2.1 常按 episode 分文件；v3 将多个 episode 打包到共享数据/视频文件，用元数据索引并支持更高效的大规模访问与 streaming。不要只改版本号或依赖路径格式，需用兼容工具迁移并读回比对。[LeRobot 官方 v3 说明](https://huggingface.co/blog/lerobot-datasets-v3)。

## Q30. UMI 与机器人数据对齐

先统一时间轴和采样周期，再将 UMI 夹爪轨迹表示成机器人可理解的 TCP 相对位姿、夹爪开合及必要的观测；核对外参、手持工具到 TCP 的偏置、尺度、旋转约定和动作延迟。机器人可达范围、动力学及夹爪差异会造成域偏移，必要时重定向并补充真机数据。

可对光照、背景和合理的初始物体位姿做增强，但几何变换必须同步更新图像、动作和坐标；不合理缩放、翻转或改变接触几何可能制造不可能的示范。最终要看真实机器人成功率，而非仅看增强后的 loss。

## Q31. 轨迹清洗与重采样

先按 episode 检查时间戳、缺失帧、关节/夹爪限位、速度和跳变，再人工抽查失败原因；异常可标记或剔除，不能把有价值的恢复数据一律删除。关节可用低通或平滑滤波，注意相位滞后；姿态应在旋转流形上插值，不能对欧拉角直接跨 ±π 平均。

降采样前考虑抗混叠，对图像、状态与动作统一时间索引。若 action 是目标位姿，重采样后需重新对齐到相应未来时刻；若是增量，可能需要在坐标系中正确组合而不是简单抽一帧。检查接触瞬间是否被过滤。

## Q32. 为什么不能简单提高采集速度

相机频率、状态读取、控制下发、动作语义和策略推理频率可能不同。提高采集频率只会记录更多高度相似帧，不必然增加有效示范，还可能增加存储、传输与训练时间。模型按 30 Hz 学到的每步增量若在 60 Hz 按相同数值重复执行，可能改变真实速度；必须区分动作是目标位置、每步增量还是速度，并同步修改时间尺度和控制器。

## Q33. 所有示范都成功就一定好吗

不一定。纯成功示范覆盖专家轨迹附近的状态；模型自己执行后，微小误差会积累，进入训练中未出现过的偏离状态，缺少纠正动作。应多样化初始摆放、遮挡、速度，并采集真实偏离后的恢复；测试按未见场景独立划分，统计中间状态失败率和恢复率。注意安全地施加扰动，不应为了造失败而损坏设备。

## Q34. 失败与 DAgger 数据

记录失败类型、发生时刻、观测和机器人实际动作；DAgger 的关键是在当前策略访问到的状态上获取专家纠正标签，再把这些样本聚合训练。人工接管前后要记录控制权切换与时间戳，避免把失败动作误标为专家动作；失败数据可用于价值学习、负例或原因分析，不应无差别当正向 BC 标签。

可根据接近限位、目标偏差、碰撞风险或不确定度触发干预，并定期人工抽检。混合原有专家数据和新数据，统一标签/动作约定并留出固定测试集，检查是否遗忘。简历说引入过 DAgger，但采集规模、自动触发机制和各自贡献【待核实】。

## Q35. Subtask 语言监督

将长任务分为语义清楚的阶段，如定位、抓取、搬运、放置，并为每段标注当前子任务和切换时刻。它可能帮助模型区分相似图像下的不同行动目标，也可能引入错误切换、标签噪声和额外推理开销。

以相同数据和预算比较：只有总指令、人工子任务标签、预测子任务标签，报告整体与分阶段成功率、阶段切换错误及延迟。标签不能借助测试时不可获取的未来信息。

# 第五部分：训练、微调与复现

## Q36. π₀.₅ 应冻结哪些参数

没有唯一答案。数据少或算力受限时，可先冻结视觉/VLM 大部分参数，训练动作专家、输入输出投影或 LoRA；场景视觉差距大时逐步解冻视觉或上层主干。全量微调适应能力更强但显存、过拟合和灾难性遗忘风险更高。比较时固定数据与评测协议，报告可训练参数量、显存、时间和成功率。

模型规模及冻结量必须从实际 checkpoint 和代码按 requires_grad 统计，不能把某个版本的参数量当作通用值。简历写过全量微调与配置经验；具体训练配置、本人负责部分【待核实】。

## Q37. LoRA 用于 VLA

LoRA 将权重增量写成 ΔW=(α/r)BA，只训练低秩矩阵，可加到注意力 Q/K/V/O、FFN 或动作专家的线性层，具体由框架支持和实验决定。先用小 rank、明确目标模块，再比较不同 rank、学习率和层位；太小欠拟合，过大增加成本和过拟合。

显存受 batch、序列长度/图像 token、action horizon、激活、优化器和精度共同影响，不仅取决于可训练参数。固定 GPU 与配置，记录峰值显存、吞吐、训练时长、验证指标及真机成功率；你的实际 GPU、显存和时长【待核实】，不要凭经验虚构。

## Q38. 仿真验证与 Sim-to-Real

若没有亲自使用过某平台，应明确说“我会这样设计”，不要把 LIBERO、MuJoCo 或 Isaac 等写成已做经历。先在仿真验证观测/动作接口、因果关系与可重复的对照，再逐步随机化相机、光照、摩擦、质量、延迟及接触；到真机先空载低速，再用相同成功条件测评。仿真成功不代表真机成功，尤其是夹爪接触、柔性材料和视觉域差异。

## Q39. 复现分数有差异怎么办

小数不同不必然意味着失败，要先检查任务版本、成功定义、初始分布、种子、轨迹数量、checkpoint、预处理和控制频率。成功率是二项估计，需报告成功数/总数及 Wilson 等置信区间，而不是只比较小数点。再用官方配置与少量公开轨迹核对模型输入输出；做多种子、分任务和失败案例分析。置信区间重叠也不自动等于结果相同，需要事先确定容差和统计方案。

## Q40. 三维资产建模精度

核对 URDF 关节方向、零位、连杆长度、TCP 和关节限位；视觉网格、碰撞几何与真实外形可能不同。通过多个已知关节位形测量末端实际位置，和正运动学比较，覆盖整个工作空间；物体用量具和视觉标定交叉验证。抓取容差越小，TCP、夹爪几何与碰撞误差越重要；插装还需要接触力和柔顺模型，单纯视觉网格逼真不足以保证可迁移。

# 第六部分：强化学习与 VLA 后训练

## Q41. Flow Matching、PPO、DPO 各优化什么

Flow Matching 根据示范拟合连续动作生成速度场，属于生成式监督学习目标；PPO 通过与环境交互得到的 advantage 优化策略期望回报，限制新旧策略变化；DPO 用偏好对和参考策略优化相对偏好，常见形式是 −log σ(β[log πθ(y⁺|x)/πref(y⁺|x)−log πθ(y⁻|x)/πref(y⁻|x)])。

Flow Matching 可以是机器人 BC 的动作头；PPO 可用于可安全交互的后训练；DPO 适合有可靠偏好数据且策略似然可计算或有合理替代目标的情况。连续 flow 策略不能不加说明地直接套语言模型 token 级 DPO 公式。

## Q42. 为什么考虑 RL，机器人 RL 的困难是什么

BC 复制示范，缺乏对任务结果的直接优化，也难覆盖模型自己偏离后的状态；RL 可借助任务成功、速度、接触质量等反馈优化并学习恢复，但成功依赖探索和奖励，不是必选或保证有效。

机器人样本昂贵，环境重置和安全约束复杂，奖励常稀疏且受遮挡影响；实体动作不可回滚，时延和磨损也重要。DSRL 冻结生成策略，通过学习噪声策略引导其行为，减少更新大模型的成本；其能力仍受基础策略覆盖和噪声到动作映射限制，仍需采样、奖励和安全防护。[DSRL 论文](https://arxiv.org/abs/2506.15799)。

## Q43. PPO 与 GRPO

PPO 中 rₜ=πθ(aₜ|sₜ)/πold(aₜ|sₜ)，最大化 E[min(rₜAₜ, clip(rₜ,1−ε,1+ε)Aₜ)]；advantage 常由 value critic 和 GAE 估计。Clip 抑制过大更新，但不是严格的 KL 上界。

GRPO 对同一条件采样一组结果，以组内相对奖励（常标准化）构造优势，通常不需要单独 critic，因此可减少 value 网络开销；代价是同条件多次 rollout、组内全成功/全失败时信号弱，且真实机器人重置困难。GRPO 有不同变体，KL 和归一化设置须看具体实现；组内比较需要任务条件可比。

## Q44. RLT 的 Actor 与 Critic

RLT 的关键是从预训练 VLA 提取紧凑 RL token 作为任务相关表征，并训练小型 actor-critic 对基础动作进行强化学习式调整，同时约束策略不要无界偏离 VLA。Actor 根据表征及实现中的动作条件提出动作/修正；critic 评估状态—动作价值并由回报和 bootstrap 训练，细节以具体版本为准。

它避免每次用 RL 更新整个大型 VLA，但依然要运行骨干、采集真实交互和处理奖励、延迟及安全；不能说 RL token 消除了所有计算和交互成本。[RLT 论文](https://arxiv.org/abs/2604.23073)。

## Q45. RECAP 思路与局限

RECAP 结合演示、自主 rollout、奖励及人工干预：训练价值模型估计状态价值，利用 n 步回报和前后 value 估计局部 advantage；将 advantage 二值化作为条件训练策略，部署时选择正优势条件。它采用有 RL 语义的价值估计和条件化策略提取，不等同于 PPO，也不等同于对样本直接指数加权的 AWBC。

价值估计错误、奖励误判、离线覆盖不足、干预成本和任务迁移都可能限制效果。你的简历没有声称实施 RECAP，因此应把它介绍为学习或研究思路。[RECAP 原论文](https://www.pi.website/download/pistar06.pdf)。

## Q46. RECAP Value Model 输入输出

价值模型通常输入图像观测、任务语言及实现所用的状态等条件，输出状态的预期未来回报 V(o,ℓ)，可用分布式回报头表达，再求期望。它本身不是直接输出 Q(o,a)。可用 n 步实际回报加终点 V 减去起点 V 来估计该段动作的 advantage，再为策略训练打条件标签。

检验时按 episode/场景隔离，比较预测价值与实际回报、正负排序、校准曲线和分阶段误差；检查相同状态下时间/终止标注是否一致，并用真机策略对照判断标签是否改善任务。

## Q47. 如何证明 Advantage 有效，30% 阈值如何定

先明确“30%”是 advantage 的数值阈值、正样本分位比例、成功率门槛还是别的超参数，不能互相替代。控制数据、训练预算、策略初始化和评测条件，比较无 advantage、打乱标签、不同阈值、真实标签等组；以多个种子和独立场景统计成功率、干预率及置信区间。

如果按分位数取高质量样本，可在验证集比较 10%/20%/30%/50% 等比例的标签质量与数据覆盖；阈值只能由训练/验证确定，不得用测试集调参。没有已记录的实验，就不能声称 30% 已得到证明。

## Q48. 稀疏奖励或分类器失效怎么办

先人工抽样审核成功/失败标签，按场景、遮挡、阶段看混淆矩阵，检查 reward hacking 和时间戳；再排查策略能力、动作转换、控制延迟、训练数据覆盖等其他原因。可用人工终局标注作为高质量参照，并尝试阶段进度、接触事件等辅助信号，但要避免改变最终任务目标。

设计对照时，固定同一批轨迹和训练过程，分别用分类器标签、人工标签以及必要的混合标签；单独评估标签一致性、训练后真机成功率和标注成本。人工判断也要有一致标准与双人复核。

## Q49. AWBC 与 DAgger

AWBC 在行为克隆损失中按 advantage 分配权重，例如 w=exp(A/β) 并进行截断，L=−E[w log πθ(a|s)]，使相对高价值动作更受重视；连续 flow 头可使用相应加权生成损失，不一定有直接可用的动作对数概率。

DAgger 解决策略访问偏离状态缺少专家动作的问题，可在这些状态采集人工纠正，再将纠正样本加入训练；失败轨迹是否使用取决于标签与价值估计质量。专家介入时应区别策略动作与人工动作，避免把失败动作直接当作正例。

## Q50. RECAP 离线到在线分布偏移

线上部署会遇到离线数据少见的姿态、遮挡与接触状态，value 可能误判 OOD 状态。可以记录自主失败和人工纠正，周期性更新数据与价值模型，同时混合原始示范防遗忘；通过不确定性、工作区和反馈超时触发安全接管。评价应在未参与训练的场景、不同干扰及多轮迭代上观察成功率和事故率，不能只看离线损失。

## Q51. Advantage Head 过拟合，是否先 SFT

先排查按帧随机切分导致的轨迹泄漏、样本太少、类别不平衡、标签噪声和训练/验证分布变化，比较训练与独立 episode 验证曲线。降低容量、正则化、增加多样轨迹和重新校准标签可能比盲目增加训练更有效。

若基础策略尚不会完成任务，先做 π₀.₅ SFT 获取可用行为，再收集 rollout 训练价值/优势模型通常合理；但 SFT 并不能保证解决 value 过拟合。应对比 SFT-only、RL-only（若可行）与 SFT→RL，固定数据预算和评测协议。

## Q52. RL Token 压缩损失多少

不存在脱离模型、任务和 token 维度的固定损失比例。RL token 主要压缩任务相关表征，不一定是对原始动作序列做可逆压缩。可比较 token 对物体相对位置、接触阶段等变量的探测能力，以及不同 token 维度下的动作误差、成功率、学习速度、延迟和显存。

对精密任务还应评估闭环插入误差、失败率与干预率；低重建误差不保证对控制最关键的信息被保留。

## Q53. Kai0 为什么在叠衣服上表现较好

公开的 χ₀/Kai0 工作围绕示范分布、模型行为与实际部署分布的不一致，结合 model arithmetic、stage advantage、DAgger 纠正与时空增强/动作平滑等；这是一套数据、训练和部署方案，不能简单说“用了 RL 所以成功”。衣物具有高维形变、自遮挡、接触不确定和长时序误差，铺平及抓边可能尤为困难。

阅读结果时要核对任务、衣物种类、机械臂配置、数据量和成功定义；展示任务中的成绩不自动等于跨任意衣物、任意家庭的泛化。[项目论文与代码](https://github.com/OpenDriveLab/kai0)。

## Q54. VLA + RL 综述怎么组织

可按“基础模型与 BC → 为什么需要结果反馈 → 离线 RL/优势条件化（RECAP、AWBC）→ 在线 RL 与轻量适配（RLT、DSRL）→ 偏好优化 → 数据回流和安全部署 → 统一评测”组织。每类比较训练信号、是否更新大模型、交互成本、可用数据、动作表示、奖励和适用条件。

评测应统一真实/仿真、样本量、重置成本、任务成功率、学习曲线、OOD 泛化与安全事件。最后讨论奖励可靠性、长时任务、成本和可复现性。

# 第七部分：RTC、异步推理与动作连续性

## Q55. 同步、异步、推理期 RTC、训练期 RTC

同步：等待本次推理结束后再执行，逻辑简单但机器人可能停顿。普通异步：执行旧动作时并行推理新动作，可减少等待，但新旧块交界可能跳变。推理期 RTC：在生成新块时，利用旧块中已承诺动作作为前缀，通过推理期 inpainting/引导约束新块，兼顾异步与衔接，但可能增加推理计算。

训练期 RTC：训练时模拟不同延迟，并让模型直接根据干净的已承诺动作前缀预测剩余动作；部署时仍需异步缓冲和正确对齐前缀，但不再需要原 RTC 的推理期梯度引导。比较时需区分算力、等待、动作边界和反馈新鲜度。[训练期 RTC 论文](https://arxiv.org/abs/2512.05964)。

## Q56. Training-time RTC 训练和推理

训练时从完整动作 chunk 抽取随机长度的前缀，模拟推理期间已经承诺要执行的动作；前缀以干净动作条件输入，后缀仍根据 Flow Matching 构造带噪动作及目标速度。损失主要施加于需要预测的后缀，具体 mask、时间条件和采样分布依实现确定；核心是让模型学会“已承诺前缀之后如何继续”。

推理时异步读取旧计划中对应的未来承诺前缀，并让模型以该前缀为条件生成后续动作，避免推理期额外 inpainting 梯度。“推理和原来没区别”只在网络主体与常规采样形式大体相同、无需额外昂贵引导的意义上成立；输入前缀、对齐、缓冲和训练权重都可能变化，不能理解为运行时无需任何协调。

## Q57. 最新状态重新规划剩余动作

假设 t 时刻启动推理，推理延迟内控制器仍在执行旧计划；这期间已发出或已经承诺执行的动作不能事后改写。新计划应以上次观测为条件，并与延迟期间承诺的前缀在时间上对齐，再决定尚未执行的后缀。重新规划使用的是**启动该次推理时可获得的最新观测**；推理结束时环境可能已进一步变化，不能说新计划自动知道未来的新状态。

简单立即替换整段旧轨迹可能使目标位置/速度突变，也可能重复执行旧动作或覆盖已下发动作。若出现重大安全事件，安全停止优先于为了平滑而维持旧动作。

## Q58. 如何保证前后缀连续

首先用时间戳确定旧块与新块的相同物理时刻，并明确动作是绝对目标、增量还是速度。对已承诺前缀进行条件约束；可在可修改的重叠区做插值或加权融合，并检查位置 C0、速度 C1 和必要时加速度 C2 连续性。对于关节轨迹还要考虑 jerk、限位和碰撞；旋转应做球面插值或合适的流形插值。

验证时记录边界前后位置差、有限差分速度/加速度/jerk、夹爪事件与任务成功率；平滑窗口太长会延迟闭环响应，不能只追求视觉上的平滑。

## Q59. RTC 的 KV Cache 如何复用

若同一次 Flow Matching 采样的图像、语言、状态前缀及 mask 固定，其各层可缓存的 K/V 可在多个去噪步中复用；具体还要看模型的注意力依赖。动作后缀、流时间条件每一步变化，通常需重新计算相关部分。新的相机帧、状态、指令或改变的已承诺动作，所依赖的缓存需重新计算，不能盲目跨 chunk 使用。

训练期通常要保留正确的梯度路径和随机增强，不能直接复用前一次参数更新或不同样本的缓存；推理缓存是计算优化，不改变 RTC 的训练目标。普通自回归 KV cache 逐 token 增长，flow 采样中固定条件缓存的复用模式不同。

## Q60. Training-time RTC 为什么可能适合双臂叠料箱

双臂共同搬运/组装时，一臂动作会改变另一臂的可达空间与接触力；异步推理的停顿和块边界跳变可能破坏协同。RTC 可在模型有推理延迟时保持动作持续，并降低新旧块之间的计划不一致；但它不自动保证两臂互避、受力平衡或任务必然成功。

验证应固定模型、数据、频率和物体配置，对比同步、普通异步、推理期 RTC 和训练期 RTC，测成功率、周期、P95 延迟、两臂相对位姿误差、边界 jerk 与接触异常。叠料箱是题目场景，不默认是你已完成的项目。

## Q61. RTC 如何持续执行，缓冲耗尽怎么办

控制线程按确定时钟从动作 buffer 读取并下发，推理线程异步消费带时间戳的观测并产生新 chunk；以单调时钟、序号和锁/无锁队列管理数据，防止旧结果覆盖新结果。推理耗时可能波动，buffer 应覆盖合理尾延迟并设置水位报警。

如果旧轨迹将耗尽且新轨迹未到，按硬件安全策略受控减速并保持/停止，必要时触发急停；不要无限重复相对增量或盲目外推。记录控制命令、实际反馈、推理开始结束和 buffer 水位，验证超时与恢复。

## Q62. 45 Hz 与 60 Hz 的问题

45 Hz 不是 RTC 的通用要求，也不能从题目推断你实际用了它。若某系统 45 Hz 正常、60 Hz 动作剧烈，先核对训练动作周期与执行周期、目标位置/速度/增量语义和单位。每步增量原样从 45 Hz 提到 60 Hz，相同时间累计幅度可能变大；绝对位置命令则不一定有这一问题。

再检查积分器、重采样、丢包重复、插值、滤波相位、伺服参数和线程竞争。用录制数据离线重放并逐层记录真实 dt、输出命令与反馈，先停止自动运动再分层测试，避免把现象直接归咎于模型。

# 第八部分：运动控制与仿真

## Q63. IK 多解如何保持连续

以当前关节角或上一时刻解为种子，选择满足关节限位、碰撞约束且与当前姿态距离最小的可行解；连续关节需考虑角度环绕。靠近奇异位形时可用阻尼最小二乘，降低速度或调整路径，但不能消除所有不可达情况。对解序列做速度、加速度、jerk 检查并限制突变；无解时停下或重规划，不应强行执行。还要核对 TCP、坐标系与旋转插值。

## Q64. 五条 LeRobot 轨迹如何画六轴机械臂运动

先读取每条 episode 的 state，确认其中确实含六个关节位置，核对顺序、单位、时间戳与 URDF；若数据仅含末端位姿，不能假装有完整关节轨迹。利用匹配的机器人 URDF 做正运动学，求每帧各关节和末端在基坐标下的位姿，绘制五条末端 3D 曲线，并用骨架随时间播放。

对比起点、工作空间、关节限位、速度跳变、末端穿模与相机图像；图形要保持坐标轴比例一致。五条轨迹是题设，验证前不可假称已绘制或已发现异常。

## Q65. 是否加入力觉/触觉

视觉容易受遮挡和反光影响，无法直接判断接触力、微小滑动和夹爪内部受力。六维力/力矩传感器可提供整体受力与力矩；指尖触觉可描述局部接触分布、滑移等，但增加标定、同步、硬件与故障成本。

可先在接近/接触阶段将力觉与视觉状态融合或交给低层阻抗控制；在同场景下比较视觉、视觉+力觉，并测成功率、接触峰值、损伤和误触发，确定传感器是否真正提供增益。简历未说明已部署力觉，不能编造成经历。

## Q66. 如何提高插入成功率

分解误差来源：定位和标定、抓取姿态、物体尺寸、末端工具、IK/轨迹、接触力及通信延迟。先在无接触或低速条件验证位姿误差，再通过合理的对准、导向、柔顺/阻抗控制及必要的力觉搜索减小接触偏差；也可以收集偏差和恢复数据改进策略。

按“接近—对准—接触—插入”标记失败阶段，分别做视觉精度、定位误差、接触峰值、插入力和成功率对照；单独改变一类因素，避免同时改模型与夹具导致无法归因。

## Q67. 为什么铺平可能容易失败

布料铺平涉及形状变化、自遮挡、双臂协调及与桌面摩擦，单帧难以判断褶皱与受力；一旦初始抓点或拉伸方向错误，后续折叠会持续累积误差。但哪一阶段最难应由真实项目日志决定，不能根据题目直接宣称你的项目中铺平最差。

可统计每个阶段的进入次数、条件成功率、主要失败模式与恢复率；针对薄弱阶段增加困难初态、视角及纠正示范，再固定其余阶段做消融。

## Q68. 迁移到双足人形机器人

先确定是否固定站立或需要移动；双足人形除了上肢任务，还要控制重心、足底接触、平衡及自碰撞。重新处理相机视角、手臂自由度、灵巧手、坐标系、动作维度和数据分布；高层 VLA 可输出任务/末端目标，低层全身控制器负责平衡与安全。

应先做仿真和固定支撑测试，再逐步转真机，评估硬件接入、数据采集、模型适配、平衡控制、安全和测试。时间取决于平台成熟度、团队与任务复杂度，不能在缺少约束时给确定周期。你的 G1 数据经历可作为基础，但不等于已经完成双足动态操作迁移。

## Q69. 低频 VLA 如何接高频控制

策略按较低频率获取观测并预测动作/动作块；高频控制循环根据明确的动作语义进行时间插值、限幅、IK/轨迹跟踪，再交给关节伺服。比如 10 Hz 策略与 500 Hz 伺服只是示意，不代表项目实测。末端增量需要按训练周期和坐标系解释，不能在每个高频周期重复累加。

监测传感器新鲜度、控制反馈、目标速度/加速度、力和碰撞；超时按设备安全规范停机。记录策略预测时刻、控制下发时刻、实际响应时刻来分析闭环延迟。

## Q76. 项目里的 30 Hz 是什么

题库只提出 30 Hz，并未证明你的项目实际以该频率运行。首先问清它指相机、数据采样、动作时间步、策略调用还是控制指令频率；模型一次可以输出 H 个动作，若每步定义为 1/30 秒，它不意味着模型每秒推理 30 次。实际策略调用频率取决于每次执行多少步及异步调度。

“前两帧特殊处理”也要以代码和日志为证；常见可能性包括缓存预热、滤波初始化、等待状态同步，但这些只是排查假设。应检查时间轴、实际下发频率、动作单位及重复执行。

## Q77. 主从臂不齐为何偶发抖动

固定标定误差可能持续存在，但是否表现为抖动还受姿态、速度、接近关节限位或奇异位形、时间戳抖动、设备丢包、目标切换和控制饱和影响，所以不一定每次都出现。若 VR/主臂使能时零点没正确记录，重连瞬间也可能突变。

排查时同步记录主端原始位姿、零点、变换后目标、机器人实际反馈、控制周期、限幅标志和通信错误；按事件前后窗口复盘，并单独测试标定、滤波、通信和执行器。你的简历确实提到相对零点、低通和限幅，但偶发抖动的根因必须由日志确认。

## Q78. 真机实际问题与排查

参考表达：“真机问题我会先定位数据链路，再定位模型和控制。相机先看帧号/时间戳和断流；状态先看连接、过期和单位；模型先用录制输入离线复现；控制侧检查动作反归一化、坐标、限幅、队列和 SDK 返回值；最后做分层联调和异常恢复。”

此前项目讨论涉及 O6 通信故障、GELLO 串口初始化等，若你亲自处理过，可补充具体现象、根因、操作和验证。题目提到 Piper SDK 冲突，但现有简历不支持该事实，应说【是否使用及冲突细节待核实】，不能把它讲成真实经历。区分掉帧、命令超时、资源冲突和线程阻塞，逐项提供日志证据。

## Q79. 如何证明 100 ms 低延迟

先定义 100 ms 的起点和终点：纯模型前向、完整多步生成，还是从相机曝光/采集到首个命令被控制器接收，甚至到物理响应。GPU 测量需要预热并正确同步，避免只测异步 kernel 提交；端到端需统一时钟并包含编码、网络、排队、动作转换及控制器处理。

报告硬件、模型版本、输入分辨率、batch、采样步数、测试次数及 P50/P95/P99/最大值；区分平均值与尾延迟。再结合 buffer 覆盖时间及任务动态论证是否满足实时性。简历没有 100 ms 指标，不能直接声称达到。

## Q80. 如何证明连续运行三小时

需要相机掉线重连、状态过期和命令超时检测，推理队列上限、动作 buffer 水位控制、异常安全停止、资源释放和健康监控。日志记录帧率、内存/显存、线程心跳、温度、超时次数、干预、成功/失败和停机时刻；必要时做故障注入。

实际连续运行并记录 ≥3 小时后，才能说该测试运行了三小时，还要说明是否有人工重启、任务复位及中断；一次三小时不等于长期可靠性得到统计保证。先前工作中的离线测试或模拟通过不能替代真机长稳测试。

# 第十部分：编程语言与工程基础（非手写题）

## Q102. 线程和进程有什么区别，如何选择

进程通常拥有独立地址空间，隔离性强，但启动、内存和进程间通信成本较高；线程共享进程内存，通信方便，但需要处理数据竞争、锁和死锁。异步 I/O 用事件循环在等待期间切换任务，适合大量非阻塞 I/O，但单个阻塞调用会卡住事件循环。

在常规启用 GIL 的 CPython 中，多线程对纯 Python CPU 密集计算通常不能实现多核并行；I/O 等待或释放 GIL 的 NumPy/PyTorch 等原生代码是不同情况，free-threaded 构建也不同。CPU 密集可考虑多进程/原生扩展；相机 I/O、通信与控制可分线程或进程，但机器人控制还需确定性、超时、共享数据一致性和安全停机，不能只按吞吐量决定。

## Q103. Python 装饰器

函数是一等对象，可以作为参数传入并返回。装饰器接收函数，返回包装后的函数；闭包可保存配置，在调用前后增加计时、日志、缓存或权限检查。带参数的装饰器通常多一层工厂函数：先接收参数，再返回真正装饰器。

使用时要注意 functools.wraps 保留元信息、异常是否被吞掉、重试是否导致机器人命令重复执行，以及线程安全。对运动指令尤其不能无条件重试非幂等操作。

## Q104. C++ Struct、Union、内存和多线程

C++ 的 struct 和 class 默认成员访问权限/继承权限不同，二者都可有成员函数；union 的成员共享存储，大小至少容纳最大成员并受对齐影响，任意时刻只能按对象生命周期规则使用有效成员。不能简单把 union 当所有成员同时存在的独立存储。

栈对象通常自动管理生命周期，动态分配对象应优先由 RAII 和智能指针管理：unique_ptr 独占，shared_ptr 共享所有权并有引用计数开销；避免循环引用。多线程使用 mutex、condition_variable、atomic 等保证同步，统一锁顺序和缩短锁持有时间以减少死锁。C++11 起函数内局部静态对象初始化具备线程安全保证，可用于 Meyers singleton，但对象自身后续操作不因此自动线程安全；析构顺序和测试耦合也要考虑。
