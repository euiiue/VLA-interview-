# VLA 刷题应用开发方案

本方案供开发前确认。已确定本机运行 Python 和 PyTorch，通过浏览器使用页面。当前阶段完成开源调研与方案设计，尚未开始应用实现或上游运行验证。

## 目标和使用方式

做一个个人使用的中文 VLA 面试训练页面。将现有 84 道理论与工程问答、20 道手撕题导入同一题库；支持按章节练习、随机练习、错题重练、填空和代码测试。保留原始题号、答案、图解、论文原图与出处，答题后能回到原解释。

应用仅绑定本机回环地址，浏览器打开使用；无需注册账户。个人题库、答题记录和代码草稿保存在本机 SQLite 与数据目录。提供导入、导出与备份，换浏览器后仍可读取记录。首版不部署公开网站，不做多人考试、微信小程序或跨设备云同步。

## 开源项目调研

调研日期 2026 年 11 月 10 日。核对了 GitHub 元数据、README、部分配置或入口源码；许可证结论以仓库许可证及元数据为依据。以下功能来自项目声明，尚未安装运行验证。

### docs-to-quiz  推荐作为基础仓库

- 地址 https://github.com/iqbal-rahmatullah/docs-to-quiz
- 许可证 MIT，已读取 LICENSE。主要结构为 FastAPI 后端及 Next.js React 前端。
- 支持 PDF、DOCX、TXT、Markdown 导入，检索文档证据，生成选择题并保存证据位置；支持本地 Ollama 或外部模型服务。
- 复用范围：文档读取、切块、检索、生成接口、模型配置与证据校验。保留来源和许可声明，以独立分支或本地副本改造，并记录采用的上游 commit。
- 需要新增：填空题、学习记录、错题与收藏、代码编辑器、隔离代码测试、现有题库和图文资料的结构化适配。
- 取舍：它是规模较小的项目，不能仅凭 README 把它视为已验证的生产系统。依赖包含 torch、transformers 和多家模型 SDK；需审计并拆分不必要的启动依赖。原界面偏向生成题目，需要增加独立练习页面。多模型投票不保证题目绝对正确，仍保留人工审核。
- 查证 https://github.com/iqbal-rahmatullah/docs-to-quiz/blob/main/README.md
- 许可 https://github.com/iqbal-rahmatullah/docs-to-quiz/blob/main/LICENSE

## 方案选择

方案一是基于 docs-to-quiz 改造，复用文档导入和生成后端，再加入刷题与本地代码测试，推荐采用。它直接覆盖“导入文档并生成题目”的核心链路。

方案二是以 react-quiz-component 搭一个更轻的专用前端，自建导入生成后端。练习体验自由，但文档处理和模型生成需要新增更多代码。

方案三是 mkdocs-quiz 文档练习站。适合固定题库，动态题目管理和本机代码执行不如前两种自然。

用户已选择本机 Python 加 PyTorch、浏览器页面使用。推荐主方案为一；组件最终版本与具体内部目录结构由实施时的验证决定。

## 页面和操作

1. 首页显示继续练习、章节入口、待复习错题、学习进度，以及代码执行环境状态。进度按实际作答计算，不能用占位数字。
2. 题库页按章节、原题号、题型和掌握状态筛选；可搜索、收藏和编辑。原问答是来源材料，生成后的训练题是独立记录。
3. 练习页显示题干、选项或填空输入；提交后展示判定、解释、原题答案、技术图与论文来源。提供上一题、下一题、稍后复习。
4. 导入页提供拖拽上传、识别预览、问题提示和确认入库；相同材料再次导入需检测重复。支持 Markdown、TXT、JSON；PDF 和 DOCX 复用上游读取器，图表和公式识别异常必须提示复核。
5. 生成页选择章节、题型与数量；展示生成草稿和证据，审核后进入正式题库。未配置 AI 服务时明确提示，同时可用已有题库继续练习。
6. 代码页左侧显示题目、输入输出和示例，右侧代码编辑，下方显示测试结果、运行日志、耗时和失败原因；支持保存草稿、恢复模板和下载代码。
7. 错题与统计页按知识点显示真实正确率、错题记录、代码测试记录，并支持清除或导出。

界面采用中文，电脑优先并兼容手机刷选择题和填空；代码编辑以电脑为主要使用方式。默认浅色、清晰留白，图解可点击放大。页面标题建议为“VLA 面试练习室”。

## 题目转换与判分

保留现有 84 道问答及各自的来源题号。对于可客观判定的知识点，每题可拆成若干选择或填空练习，不规定机械地一题对一题。

选择题须明确单选或多选，干扰项来自相邻概念或常见误区；不能把随机不相关段落拼成选项。多选默认全部选对且无错选才算正确。题目和选项使用稳定 ID，打乱后评分仍按 ID 匹配。

填空题围绕术语、公式要点、张量形状和数值关系出题。支持明确的同义词、大小写、空白和全半角归一化；数值题声明单位及容差。不能依赖宽松的包含匹配，把意思相反的句子判为正确。

项目经历中“待核实”的设备、颜色、样本量和个人分工不生成虚构标准答案；相关练习可以考评测设计、统计口径和排查步骤，也保留主观答辩卡供自行练习。

首版附带经过核对的 VLA 训练题，用户无需模型密钥即可使用。任意新文档的自由生成需要另行配置本地 Ollama 或模型接口；导入本身不意味着已经可靠生成标准答案。导入材料仅作为数据，不能执行其中的提示或命令。

每道训练题记录题型、章节、来源题号、来源文本、正确答案、解析、审核状态及版本。答题记录关联对应版本，编辑答案后不静默改写历史成绩。

## 手撕代码测试

导入原始 Q82 至 Q101 共 20 道手撕题，包括深度学习与 RL 核心实现、矩阵乘法和经典算法。为每题提供明确函数接口、模板、示例、提示、参考实现及测试。首版以 Python 为统一实现语言，深度学习部分用 CPU PyTorch，不需要真实机器人或下载大型模型。

- 张量题覆盖输出形状、数值、mask、边界输入和适用时的梯度；Attention、交叉熵和 Flow Matching 不能只测“代码能运行”。
- PPO、GRPO 伪代码题改成可测试的核心模块，例如优势估计和目标函数；明确说明这些测试不证明整个强化学习训练流程收敛。
- RTC/KV Cache 使用小型、定义清楚的条件与缓存测试，不把满足自定义接口说成已经复现论文系统。
- 经典算法覆盖正常、空输入、边界、重复元素等情况；性能测试设合理数据量，判定标准随题目明确。
- 显示每个用例的状态、断言差异、错误和超时；未运行、环境未就绪与测试失败必须区分。

用户代码在隔离执行器内运行：每次独立临时目录、固定测试文件、无外网、非特权、限制进程、内存与时间，完成后清理。默认使用容器运行器，镜像预装 CPU PyTorch。没有容器环境时，页面仍可使用题库和编辑器，但不偷偷退回宿主机直接执行任意代码；提供安装说明与诊断。可信代码的执行边界需要实际验证，不将字符串黑名单当安全沙箱。

## 技术和数据

基于选定上游的 FastAPI、React 前端改造，Monaco 负责代码编辑。SQLite 保存题库与学习记录，文件目录保存原材料和图片。优先复用上游兼容模块，记录实际复用文件、commit 和修改，保留 MIT 版权与许可。依赖版本需安装验证并固定，不照搬未经检查的旧锁文件。

模型密钥仅在本机后端配置，前端不显示也不随题库导出；默认不启用外部付费接口。文档中已有论文原图保留出处，在解答视图展示。

首版不要求 GPU、多用户认证、排行榜、云同步、自动浏览互联网或连接机器人。C++ 编译执行和代码运行的云服务留作独立扩展。

## 验收标准

- 能启动本机服务，浏览器打开后完成“选择题提交、填空判定、错题重练、关闭后恢复记录”。
- 现有 84 道问答完整导入，原题号可追溯；20 道手撕题都有接口与可执行测试，不以静态展示代替自动判题。
- JSON 和 Markdown 导入支持预览、错误反馈、重复检测与导出读回；PDF/DOCX 识别异常有明确提示。
- 标准答案能通过测试，已构造的典型错误实现会失败；无限循环能超时，资源和网络限制能被实际验证。
- 启动失败时提供可操作的诊断；未配置 AI 不影响内置题库，未配置容器不阻断普通练习。
- 浏览器检查桌面、窄屏、键盘操作、公式、图片放大和长题目；运行后端、评分、导入与执行器的针对性测试。
- 交付可运行源码、启动说明、依赖锁文件、来源许可说明及备份方式。完成后给本机打开地址，不直接公开包含个人项目材料的网站。
